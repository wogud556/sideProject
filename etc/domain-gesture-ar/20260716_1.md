## 1. 프로젝트 개요

PDF 이력서를 업로드하면 시스템이 텍스트를 추출·분석해 인적사항, 학력, 경력,
프로젝트, 자격증, 기술, 어학 항목으로 자동 분류하고, 웹 화면에서 검토·수정할
수 있는 웹 애플리케이션. 경력에 기재된 기업명은 금융감독원 OpenDART 기업
데이터와 매칭해 기업개황과 최근 사업연도 주요 재무정보(자산/부채/자본/매출/
영업이익/당기순이익)를 조회할 수 있다.

### 원 명세 대비 확정된 조정사항 (사용자 결정)

| 항목 | 원 명세 | 실제 구현 |
|---|---|---|
| 데이터 저장 | PostgreSQL | **DB 전혀 없음 — 모든 데이터를 `data/` 폴더의 JSON 파일로 저장** (로그인 계정 포함) |
| 비동기 처리 | Celery + Redis | **동기 처리** (업로드 요청 안에서 분석까지 완료) |
| 구조화 | LLM + 규칙 | **규칙 기반 파서 기본, LLM은 공급자 인터페이스만 정의(스텁)** |
| 실행 환경 | Docker Compose | `pip install` + `runserver`만으로 실행 (Docker/Redis/DB 서버 불필요) |

> 조정 이유: 사용자가 데이터베이스를 전혀 모르는 사람이라는 전제. 저장된
> 데이터는 사람이 직접 열어볼 수 있는 JSON 파일이며, 분석 결과는 화면에서
> Excel(.xlsx)로 다운로드할 수 있다.

## 2. 개발 프로세스 (에이전트별 수행 내역)

### 2.1 planner — 요구사항 분석·작업 계획
- SPEC.md(조정 명세)를 분석해 8단계(Phase 0~8) 구현 계획 수립
- 산출물: `resume_intelligence/SPEC.md`, `resume_intelligence/PLAN.md`
- 핵심 설계 판단: 무DB Django 구동법(`DATABASES={}`, signed_cookies 세션,
  contrib.auth 미사용), 테스트 전략(SimpleTestCase 전용 + NoDatabaseTestRunner),
  JSON 저장소의 원자적 쓰기 설계, DART 장애 격리 원칙

### 2.2 developer — 전체 구현
- Phase 0~3: Django 스켈레톤, `storage/json_store.py`(임시파일+rename 원자적
  쓰기, 경로별 Lock), JSON 파일 기반 인증(accounts), PDF 분석 라이브러리
  (pdf_analysis) — 이 시점 테스트 121개 통과
- Phase 4~8: 이력서 업로드/상세/수정 화면과 REST API(resumes), OpenDART
  연계(dart), 통합 배선, 보안 점검, README — 테스트 269개 통과
- 실서버(runserver) + curl로 회원가입→업로드→분석→수정→Excel 다운로드→DART
  안내 흐름을 수동 검증
- 개발 환경 준비 과정에서 Python 3.12, Tesseract 5.5(한국어 언어팩 포함)를
  Homebrew로 설치

### 2.3 reviewer — 코드 리뷰
발견: HIGH 2건, MEDIUM 6건, LOW 8건. 주요 지적:

| 심각도 | 내용 |
|---|---|
| HIGH | API 전체가 `@csrf_exempt` + 세션 쿠키 인증 조합 → CSRF 공격으로 이력서 삭제/수정 위조 가능 |
| HIGH | 저장소 락(`update_json`)을 실제 쓰기 경로가 우회 → 동시 요청 시 수정사항 유실(lost-update) |
| MEDIUM | 기간 검증 규칙(입사일≤퇴사일, 중복 기간)이 파이프라인에 미연결(dead code) |
| MEDIUM | GET 요청에서 DART 자동 연결 부수효과 (크로스사이트 GET으로 트리거 가능) |
| MEDIUM | 회원가입 중복 검사 TOCTOU 레이스 (동일 아이디 2명 생성 가능) |
| MEDIUM | DART 비-JSON 응답 시 500, corp_code/year/report_code 검증 산재·누락 |

### 2.4 developer — 리뷰 반영
- CSRF: `@csrf_exempt` 전부 제거, `GET /api/v1/csrf`로 토큰 발급 후
  `X-CSRFToken` 헤더 검사 (실서버로 403/200 검증)
- 동시성: 모든 read-modify-write를 락 기반 `update_document`/`update_profile`로
  교체 — 20개 스레드 동시 수정 테스트로 유실 없음 확인
- 나머지 MEDIUM 6건·LOW 2건 전부 수정 + 회귀 테스트 30개 추가 → 299개 통과

### 2.5 tester — 테스트 보강·최종 실행
- SPEC 테스트 명세·완료 기준 대비 커버리지 매트릭스 작성
- 공백 8건 보강: 정확히 20MB/30페이지 경계값, 특수문자·깨진 인코딩 파일명,
  비정상 연락처 형식 파이프라인 완주, Excel 7개 시트 셀 단위 정합성,
  DART 미등록(NOT_FOUND) 뷰 시나리오, **업로드→분석→수정→확인→DART 검색→
  기업선택→개황→재무까지 한 흐름의 E2E 테스트**
- **실제 버그 1건 발견·수정**: 깨진 인코딩(lone surrogate) 파일명 업로드 시
  `document.json` 기록 단계에서 `UnicodeEncodeError`로 500 에러 →
  저장 직전 파일명 정리(`_sanitize_filename`)로 수정, 회귀 테스트 추가
- 최종: **307개 테스트 통과 (실패 0)**

```
resume_intelligence/
├── manage.py
├── requirements.txt
├── .env.example              # DJANGO_SECRET_KEY, DART_API_KEY
├── README.md                 # 상세 실행 안내
├── SPEC.md / PLAN.md         # 조정 명세 / 구현 계획
├── config/                   # settings(DB 미설정), urls, test_runner
├── storage/
│   └── json_store.py         # read_json / write_json(원자적) / update_json(락)
├── apps/
│   ├── accounts/             # JSON 파일 기반 회원가입·로그인, login_required
│   ├── pdf_analysis/         # 순수 라이브러리 (파일 저장 안 함)
│   │   ├── schemas/          # Pydantic: ExtractedField, ResumeProfile 등
│   │   ├── validators/       # 파일 검증(20MB/30p/암호화), 필드·기간 검증
│   │   ├── extractors/       # PyMuPDF / OCR / Hybrid(품질 낮은 페이지만 OCR)
│   │   ├── parsers/          # 섹션 탐지, 규칙 기반 파서, LLM 스텁
│   │   └── pipeline.py       # run_pipeline: 추출→품질평가→OCR→구조화→검증
│   ├── resumes/              # 업로드/상세/수정 화면 + /api/v1/ + Excel 내보내기
│   └── dart/                 # 기업 동기화·매칭·개황·재무 (resumes와 독립)
├── templates/  static/
├── data/                     # ★ 모든 데이터 (사람이 직접 열어볼 수 있음)
│   ├── users.json
│   ├── resumes/{uuid}/       # document.json, original.pdf, blocks.json, profile.json
│   └── dart/                 # corporations.json, profiles/, financials/
└── tests/                    # 307개 (fixtures, 합성 PDF 헬퍼 포함)
```

### 처리 흐름 (동기)

```
PDF 업로드
 → 검증 (확장자·MIME·PDF 시그니처·20MB·30페이지·암호화·빈 PDF)
 → data/resumes/{uuid}/original.pdf 저장
 → PyMuPDF 페이지별 텍스트 블록 추출 (좌표 보존)
 → 페이지 품질 평가 → 품질 낮은 페이지만 OCR (kor+eng)
 → 섹션 탐지 → 규칙 기반 필드 추출 → Pydantic 검증 → 기간·형식 검증
 → profile.json 저장 (항목별 신뢰도·원문 근거·검토필요 표시)
 → 상세 화면에서 사용자 검토·수정 → 확인 완료
```

DART 매칭은 별도 화면에서 사용자가 트리거하며, 완전일치 1건이면 자동 연결
후보(버튼으로 확정), 복수 후보면 사용자가 선택, 미등록이면 NOT_FOUND 안내.
DART 키 미설정·장애 시에도 이력서 기능은 전혀 영향받지 않는다.

## 5. 주요 기능

1. **회원가입/로그인** — `data/users.json`, 본인이 올린 이력서만 접근 가능
2. **PDF 업로드** — 드래그 없이 파일 선택, 제약·개인정보 안내 표시
3. **자동 분석** — 텍스트 PDF는 직접 추출, 스캔 PDF는 OCR (Tesseract 미설치
   시 경고만 남기고 진행)
4. **분석 결과 검토·수정** — 탭(기본정보/경력/학력/프로젝트/자격증/기술/원본
   텍스트), 항목별 신뢰도·검토필요 뱃지, 경력·학력 추가/삭제, 확인 완료,
   재분석(사용자 수정값 보존)
5. **Excel 다운로드** — 분석 결과 7개 시트
6. **DART 기업 매칭** — 기업명 정규화(㈜/주식회사 등 제거) 후 후보 검색·선택·해제
7. **기업 상세** — 개황 + 최근 사업연도 재무 6계정 + 출처 안내 문구
8. **REST API** — `/api/v1/resumes...`, `/api/v1/dart/...` (세션 + CSRF 토큰)

## 6. 실행 방법

### 6.1 요구사항
- Python 3.12 이상 (개발 머신에는 Homebrew로 설치됨: `brew install python@3.12`)
- (선택) Tesseract — 스캔 PDF OCR용: `brew install tesseract tesseract-lang`
  - 미설치여도 텍스트 PDF 분석은 전부 동작

### 6.2 설치·기동

```bash
cd sideProject/etc/resume_intelligence

# 가상환경이 이미 있으므로 바로 실행 가능:
.venv/bin/python manage.py runserver

# 처음부터 다시 만들 경우:
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py runserver
```

브라우저에서 `http://127.0.0.1:8000` 접속 → 회원가입 → 로그인 → PDF 업로드.
DB 마이그레이션 등 별도 준비 과정 없음.

### 6.3 DART 연동 (선택)

```bash
# 1. https://opendart.fss.or.kr 에서 무료 API 키 발급
# 2. .env.example을 복사해 .env 생성 후 DART_API_KEY 입력
# 3. 기업 고유번호 동기화 (1회):
.venv/bin/python manage.py sync_dart_corporations
```

키가 없으면 매칭 화면에 안내 문구가 표시될 뿐, 이력서 기능은 정상 동작한다.

### 6.4 테스트 실행

```bash
.venv/bin/python manage.py check    # 시스템 점검
.venv/bin/python manage.py test     # 307개 (외부 API 호출 없음, 전부 Mock)
```

### 6.5 윈도우 환경에서 실행

코드는 수정 없이 윈도우에서 그대로 동작한다 (모든 파일 IO가 UTF-8 명시,
`pathlib` 경로, `os.replace`는 윈도우 지원 함수). 단, 맥에서 만든 `.venv`
폴더는 맥 전용 바이너리라 윈도우에서 재생성해야 한다.

1. **Python 3.12 설치** — python.org 설치 파일 실행, 첫 화면에서
   **"Add python.exe to PATH" 반드시 체크**
2. **프로젝트 복사** — `.venv/` 폴더는 제외하고 복사 (git clone 권장)
3. **가상환경 생성 + 패키지 설치** (명령 프롬프트/PowerShell):
   ```bat
   cd resume_intelligence
   py -3.12 -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
4. **서버 실행**: `python manage.py runserver` → `http://127.0.0.1:8000`
5. **(선택) Tesseract OCR** — 스캔 PDF 사용 시에만:
   UB Mannheim 설치 파일(github.com/UB-Mannheim/tesseract/wiki) 실행,
   설치 중 "Additional language data"에서 **Korean 체크**,
   설치 후 PATH에 `C:\Program Files\Tesseract-OCR` 추가.
   미설치여도 앱은 정상 동작 (스캔 PDF에만 OCR 불가 경고)
6. **(선택) DART 연동** — 맥과 동일 (`.env` 작성 후
   `python manage.py sync_dart_corporations`)

맥과 다른 점 요약:

| 항목 | 맥 | 윈도우 |
|---|---|---|
| 가상환경 활성화 | `.venv/bin/python` | `.venv\Scripts\activate` 후 `python` |
| Tesseract 설치 | `brew install tesseract` | UB Mannheim 설치 파일 + PATH 등록 |
| Python 설치 | brew 또는 기본 | python.org 설치 파일 (PATH 체크 필수) |

## 7. 보안 적용 내역

- 로그인 필수, 본인 소유 이력서만 접근 (비소유자·임의 UUID는 404)
- PDF는 소유자 검사 뷰를 통해서만 서빙 (파일 경로 직접 노출 없음)
- 확장자 + MIME + `%PDF-` 시그니처 동시 검사, UUID 저장 경로, sha256 중복 탐지
- API 상태 변경은 CSRF 토큰(`X-CSRFToken`) 필수
- corp_code(`^[0-9]{8}$`)·year·report_code 화이트리스트 검증 (경로 조작 차단)
- 로그에 이력서 원문·전화·이메일·생년월일·API 키 미기록 (코드 전체 확인)
- 주민등록번호·사진·민감항목(성별/종교 등)은 스키마에서 아예 제외

## 8. 알려진 제한사항

- **동기 처리**: 페이지 수가 많은 스캔 PDF는 업로드 응답이 느릴 수 있음
  (20MB/30페이지 사전 차단으로 상한 제한)
- **규칙 기반 파서**: 표 형식·복잡한 디자인 이력서에서는 정확도 한계 —
  낮은 신뢰도 항목은 "검토 필요"로 표시되어 화면에서 수정하는 흐름으로 보완
- **LLM 미연동**: 인터페이스만 정의됨. 추후 API 키만 확보하면 공급자 구현체를
  붙여 정확도 향상 가능
- **단일 프로세스 전제**: JSON 파일 저장소의 락은 프로세스 내 스레드 기준
  (runserver 개발 서버 기준으로는 안전)
- **로컬 개발 전제**: SECRET_KEY/DEBUG 기본값, 쿠키 Secure 플래그 미강제 —
  외부 배포 시 반드시 변경 필요 (README에 명시)
- 이력서 수가 매우 많아지면 대시보드/중복검사(전체 폴더 스캔)가 느려질 수 있음

## 9. git 커밋 전 보안 점검 결과

커밋 전에 저장소에 올라가면 안 되는 요소가 있는지 점검했으며,
**현재 상태로 커밋해도 보안에 걸릴 요소는 없음**을 확인했다.

### 9.1 점검 결과

| 점검 항목 | 결과 |
|---|---|
| 실제 API 키/시크릿 | **없음** — `.env` 파일 자체가 존재하지 않고, `.env.example`에는 placeholder만 있음. 코드 전체 키 패턴 검색 0건 |
| 개인정보 (업로드 PDF, 계정) | **없음** — `data/` 폴더가 비어 있고, `.gitignore`에 `data/`가 등록돼 있어 앞으로 업로드해도 git에 올라가지 않음 |
| 가상환경 | `.venv/`도 `.gitignore`에 포함 (수백 MB 커밋 사고 방지) |
| 테스트 데이터 | 전부 코드로 생성한 합성 PDF + DART 공개 공시 데이터(삼성전자 corp_code 등)라 개인정보 없음 |

`.gitignore`가 `.env`(키), `data/`(개인정보), `.venv`(환경)를 전부 제외하므로
git에 올라가는 것은 순수 코드·문서·합성 테스트 데이터뿐이다.

### 9.2 참고사항 (커밋을 막는 문제는 아님)

1. **`settings.py`의 개발용 SECRET_KEY 기본값** —
   `"dev-insecure-secret-key-change-me"` 문자열이 코드에 있으나, 이는 진짜
   비밀값이 아닌 로컬 개발용 placeholder라 공개 저장소에 올라가도 유출이
   아니다. 다만 **외부 배포 시** 환경변수 `DJANGO_SECRET_KEY`를 설정하지
   않으면 누구나 세션 쿠키를 위조할 수 있으므로 배포 시 반드시 변경해야 한다
   (README 제한사항에도 명시됨).
2. **커밋 전 습관** — 추후 DART 키를 `.env`에 넣게 되면, 커밋 전
   `git status`로 `.env`가 목록에 없는지 확인할 것. 현재는 `.gitignore`가
   막아주지만, 실수로 `git add -f`를 하거나 키를 `.env`가 아닌 다른 파일에
   적으면 새어나갈 수 있다.
