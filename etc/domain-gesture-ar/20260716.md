## 개요

`domain-gesture-ar` MVP(웹캠 + MediaPipe 양손 추적 + OpenCV 이펙트 합성)는 원래 손동작 1개(검지·중지만 펼치고 양손을 모으는 자세 → "영역 전개" 이펙트)만 실제로 동작에 연결되어 있었다. `명세.md` 5장에는 확장 예시 코드 2개와, 실제 판정 로직 없이 아이디어만 있는 4개 동작→이펙트 매핑 표가 적혀 있었다.

사용자가 "인식 가능한 동작이 몇 개냐"고 물어 위 상태(구현 1개 / 예시 코드만 2개 / 아이디어만 4개)를 확인해줬고, 이어서 "아이디어로 나뉜 4개 동작까지 구현해달라"고 요청해 `main.py`에 4개 손동작을 전부 실제로 인식·발동되도록 구현했다.

## 구현 내용

### 인식되는 4개 동작 → 이펙트

| 손동작 | 이펙트 |
|---|---|
| 검지·중지만 펼치고 양손을 가깝게 모음 (기존 동작) | 푸른 무한 공간 (BLUE INFINITE VOID) |
| 양손 손바닥을 펴고 거의 겹치도록 교차 | 붉은 신전 (CRIMSON SHRINE) |
| 양손 손바닥을 펴고 화면 아래쪽에서 서로 멀리 벌림 | 검은 그림자 정원 (SHADOW GARDEN) |
| 양손 모두 엄지·검지로 원(고리) 모양을 만듦 | 황금빛 심판 공간 (GOLDEN JUDGMENT) |

### 설계 방식

1. **이펙트 렌더링 공통화**: 기존 `DomainEffect` 클래스(충격파·회전 마법진·중앙 문양·입자·가장자리 선·제목 텍스트를 그리는 로직)를 색상만 다른 4벌로 복붙하지 않기 위해, `Theme` 데이터클래스(제목/부제목 + 각 도형별 색상 팔레트)를 도입하고 `DomainEffect`를 `AreaEffect`로 일반화했다. 렌더링 코드는 한 벌만 유지하고 `effect.start(theme)`로 팔레트만 주입한다.
2. **손동작 판정 함수 추가**:
   - `matches_open_palm`: 네 손가락(검지~새끼) 모두 펼침 (손바닥 편 자세)
   - `matches_finger_circle`: 엄지 끝(4번 랜드마크)과 검지 끝(8번) 사이 거리가 임계값보다 가까움
   - `hands_are_close`에 임계값 인자(`wrist_threshold`, `index_threshold`)를 추가해, 동작마다 "가깝다"의 기준을 다르게 쓸 수 있도록 일반화 (기존 호출부는 기본값으로 동일하게 동작)
3. **4개 동작을 우선순위 목록(`GESTURE_LIBRARY`)으로 관리**: `(라벨, 판정함수, 테마)` 튜플 리스트를 순서대로 검사해 첫 번째로 일치하는 동작을 채택한다.
   - 순서: 손가락 원(가장 구체적) → 검지·중지 자세 → 손바닥 교차(가깝게) → 손바닥 벌림(멀리+아래)
   - "손바닥 교차"와 "손바닥 벌림"은 둘 다 손가락 패턴이 같아(4손가락 모두 펼침) 손 사이 거리·손목 높이로만 구분되므로, 더 구체적인 동작을 먼저 검사해 오검출을 줄였다.
4. **유지 시간·재발동 잠금 로직 일반화**: 기존에는 동작 1개 기준으로 "0.8초 유지 → 발동 → 자세 풀 때까지 잠금"이었던 로직을, 어떤 동작이 진행 중인지(`current_gesture_label`) 함께 추적하도록 확장해 4개 동작 모두에 동일하게 적용했다. 유지 중 다른 동작으로 자세가 바뀌면 유지 시간이 초기화된다.
5. **UI 소폭 개선**: 발동 대기 중 진행바에 어떤 동작을 충전 중인지 라벨을 표시(`CHARGING: <동작명>`). 수동 테스트 키(`R`)는 4개 테마 중 무작위로 하나를 재생하도록 변경(기존에는 고정 1개 이펙트만 재생).

### 새로 추가된 상수

```python
CROSSED_WRIST_DISTANCE = 0.18   # 손바닥 교차: 손목 간 거리 임계값 (기존 hands_are_close 0.38보다 훨씬 타이트)
CROSSED_INDEX_DISTANCE = 0.15   # 손바닥 교차: 검지 시작점 간 거리 임계값
FINGER_CIRCLE_DISTANCE = 0.06   # 엄지-검지 끝 거리, 이보다 가까우면 원을 이룬 것으로 판정
LOWERED_WRIST_Y = 0.6           # 손바닥 벌림: 손목 y좌표가 이보다 커야 "아래쪽"으로 판정
```

## 명세와 다르게 간 부분 / 임의로 정한 부분

명세 5장의 추천 매핑 표에는 동작 이름과 이펙트 이름만 있고 정확한 판정 기준·색상은 없었다. 아래는 이번에 새로 정한 것이며, 실제 사용해보고 인식이 잘 안 되면 임계값을 조정하면 된다:

1. **손바닥 교차 판정**: "교차"를 엄밀히(왼손이 오른쪽으로, 오른손이 왼쪽으로 넘어가는 것) 판정하려면 좌우 손 식별(handedness)이 필요하지만, 기존 코드가 손의 좌우 구분 없이 좌표만 다루서, 이번에도 "양손이 거의 겹칠 만큼 가까움"으로 단순화했다. 명세 자체가 "우선은 관절 좌표 규칙만으로 구현한다"는 MVP 원칙을 밝히고 있어 이 단순화가 기존 방향과 일치한다고 판단했다.
2. **손가락 원 판정**: "양손이 함께 하나의 원을 구성"이 아니라 "각 손이 독립적으로 엄지·검지 원을 만듦"(쌍안경 잡는 모양과 유사)으로 단순화했다. 한 손 판정 함수(`matches_finger_circle`)를 양손에 동일 적용하는 방식이 더 안정적으로 인식될 것으로 판단했다.
3. **색상 팔레트**: 각 동작 이름(푸른/붉은/검은/황금빛)에 맞춰 임의로 정한 오리지널 배색이다. 실제 저작물 이미지나 색상표를 참조하지 않았다(명세 원문 지침과 동일한 방침).

## 검증

웹캠이 없는 환경이라 실제 카메라로 재현하지는 못했고, 아래 방식으로 대체 검증했다:

1. `python -m py_compile main.py` — 문법 오류 없음
2. 가짜 랜드마크 좌표(21개 관절, x/y만 있는 더미 객체)로 22개 케이스 스크립트 실행 — 전부 통과
   - 단일 손 판정: 검지·중지 자세 vs 손바닥 편 자세 vs 주먹 vs 손가락 원 각각 올바르게 True/False
   - 양손 합성 판정: 4개 동작 각각 정상 케이스에서 True, 서로 다른 동작 조건(가까움/멂/높이)에서는 False로 오검출 없음 확인
   - `detect_active_gesture` 우선순위: 손가락 원 자세를 만들면 다른 조건과 상관없이 항상 손가락 원이 채택되는지 확인
3. 더미 프레임(640×480 검은 이미지)에 4개 테마 전부로 `AreaEffect.draw()` 실행 — 예외 없이 정상 렌더링 확인

실제 조명·각도·거리 조건에서의 인식률은 명세 6장에서도 이미 "규칙 기반 판정의 한계"로 언급된 부분이라, 실제 웹캠 테스트(`python main.py`)로 사용자가 직접 확인 필요.
