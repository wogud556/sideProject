신규 API 함수 (`api/bank_api.ts`)

```
getAccountApi(accountNumber)
openAccountApi(userId, productCode, accountName)
depositApi(accountNumber, amount, description)
withdrawApi(accountNumber, amount, description)
getTransactionsApi(accountNumber)
approveLoanApi(applicationId)
disburseLoanApi(applicationId)
repayLoanApi(applicationId, repaymentAmount)
extractErrorMessage(err, fallback)   // 신규 BusinessException 응답 {success,code,message} 대응
```

기존 로그인/대출신청 에러 처리는 컨트롤러가 문자열(`e.getMessage()`)을 그대로 반환했지만, 이번에 추가한 엔드포인트들은 `GlobalExceptionHandler`가 `{success, code, message}` 객체를 반환한다. 두 형태를 모두 처리하도록 `extractErrorMessage` 헬퍼를 만들어 신규 화면에서 공용으로 사용했다.

화면 흐름

**계좌 상세 (`AccountDetail.tsx`)**
1. 마이페이지 → 계좌 카드의 "입출금 / 거래내역 →" 클릭
2. 잔액 확인 → 입금/출금 탭 선택 → 금액·설명 입력 → 처리
3. 처리 후 잔액과 거래내역 리스트 자동 갱신 (입금·대출실행금은 초록, 출금·대출상환은 빨강으로 구분 표시)

**계좌 개설 (`MyPage.tsx`)**
- "내 계좌" 섹션 하단에 계좌 이름 입력 후 "+ 계좌 개설" → 추가 계좌가 목록에 반영

**여신 화면 흐름 (`MyLoans.tsx`)**
- 상태 `심사중`: "승인 처리 (테스트)" 버튼 → 심사 자동화 없이 상태만 전환 (백엔드에 실제 심사 로직이 없어 데모용으로 노출)
- 상태 `승인`: "대출 실행하기" 버튼 → 실행금이 연결 계좌에 입금되고 상태가 `실행완료`로 전환
- 상태 `실행완료`: 남은 대출 잔액 표시 + 상환 금액 입력 후 "상환하기" → 계좌에서 출금 + 잔액 차감, 잔액이 0이 되면 "상환 완료" 표시로 전환

검증

- curl로 signup → deposit/withdraw/transactions → 계좌개설(POST /accounts) → loan apply → approve → disburse → repay 전체 흐름을 백엔드에 직접 호출해 응답값(잔액 반영, remainingBalance 갱신 등) 확인
- 신규/수정된 프론트 파일 전체 `tsc --noEmit` 통과
- `npm run dev` 구동 후 모든 신규 라우트(`/mypage`, `/account/:accountNumber`, `/my-loans`)와 관련 모듈이 Vite에서 에러 없이 서빙되는 것 확인
- 브라우저에서 직접 버튼을 클릭하는 수동 확인은 브라우저 자동화 도구가 없어 진행하지 못함 — 사용자가 직접 클릭 테스트 권장
