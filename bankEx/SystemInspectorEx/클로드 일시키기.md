아래 내용을 그대로 Claude Code에게 전달할 명세로 쓰면 됩니다. MCP는 외부 시스템/파일/도구를 AI 클라이언트에 연결하는 표준이고, Resources로 파일·DB 같은 컨텍스트를 제공하고 Tools로 실행 기능을 노출하는 구조가 맞습니다.  ￼

프로젝트 명세: Project Code Inspector MCP

1. 목표

특정 로컬 프로젝트 경로를 MCP 서버에 등록하면, Claude Code가 해당 프로젝트의 소스 구조를 읽고 분석한 뒤 사용자가 “이 결함을 수정해줘”, “이 에러 원인을 찾아줘”, “이 API 로직을 개선해줘”라고 요청했을 때 즉시 관련 파일을 찾고, 수정안을 만들고, 실제 파일에 패치를 적용할 수 있는 MCP 서버를 구축한다.

2. 핵심 요구사항

2.1 프로젝트 경로 등록

MCP 서버는 실행 시 환경변수 또는 설정 파일로 프로젝트 루트 경로를 입력받는다.

예시:

PROJECT_ROOT=/Users/me/workspace/my-project

서버는 반드시 이 루트 경로 하위 파일만 읽고 수정해야 한다. ../, 심볼릭 링크, 절대경로 우회 등으로 프로젝트 외부 파일에 접근하지 못하게 한다.

2.3 MCP Resource 제공

다음 Resource를 제공한다.

project://summary
project://tree
project://file/{path}
project://symbols
project://recent-changes

각 Resource 역할:

project://summary
- 프로젝트 이름, 언어, 프레임워크, 주요 디렉터리 요약
project://tree
- 프로젝트 파일 트리
project://file/{path}
- 특정 파일 내용 반환
project://symbols
- 클래스, 함수, 메서드, API 엔드포인트 색인
project://recent-changes
- 최근 수정된 파일 목록

2.4 MCP Tools 제공

아래 Tool을 구현한다.

1. index_project

프로젝트 전체를 다시 스캔하고 인덱스를 갱신한다.

입력:

{
  "force": true
}

출력:

{
  "indexedFiles": 120,
  "skippedFiles": 35,
  "languages": ["Kotlin", "TypeScript", "SQL"]
}

2. search_code

키워드 또는 자연어로 관련 파일을 검색한다.

입력:

{
  "query": "로그인 후 세션이 만료되지 않는 문제"
}

출력:

{
  "matches": [
    {
      "path": "src/main/kotlin/auth/LoginService.kt",
      "score": 0.91,
      "snippet": "..."
    }
  ]
}

3. read_file

프로젝트 내부 특정 파일을 읽는다.

입력:

{
  "path": "src/main/kotlin/auth/LoginService.kt"
}

4. analyze_defect

사용자가 설명한 결함을 기준으로 관련 파일을 찾고 원인을 분석한다.

입력:

{
  "defect": "로그아웃 후 Redis에 세션이 남아있음"
}

출력:

{
  "summary": "LogoutService에서 Redis delete 호출이 누락됨",
  "relatedFiles": [],
  "suspectedCause": "",
  "recommendedFix": ""
}

5. propose_patch

수정안을 unified diff 형식으로 생성한다. 이 단계에서는 파일을 수정하지 않는다.

입력:

{
  "defect": "로그아웃 후 Redis 세션이 삭제되지 않음",
  "targetFiles": ["src/main/kotlin/auth/LogoutService.kt"]
}

출력:

--- a/src/main/kotlin/auth/LogoutService.kt
+++ b/src/main/kotlin/auth/LogoutService.kt
@@ ...

6. apply_patch

Claude가 생성한 diff를 실제 파일에 적용한다.

입력:

{
  "diff": "..."
}

조건:

- PROJECT_ROOT 밖 파일 수정 금지
- 적용 전 백업 생성
- 적용 전후 git diff 출력
- 실패 시 원복 가능해야 함

7. run_tests

프로젝트 타입에 따라 테스트 명령을 실행한다.

자동 감지:

build.gradle → ./gradlew test
pom.xml → ./mvnw test 또는 mvn test
package.json → npm test
go.mod → go test ./...
Gemfile → bundle exec rspec

입력:

{
  "command": "auto"
}

출력:

{
  "success": true,
  "exitCode": 0,
  "stdout": "...",
  "stderr": "..."
}

8. explain_patch

적용한 수정 내용을 사용자에게 설명한다.

출력:

수정 파일
수정 이유
변경 전 문제
변경 후 동작
테스트 결과
추가 확인 필요사항

3. 권장 기술 스택

Language: TypeScript
Runtime: Node.js LTS
MCP SDK: @modelcontextprotocol/sdk
Validation: zod
File Search: fast-glob
Patch Apply: diff / git apply
Test Runner: child_process.spawn

5. 보안 요구사항

이 MCP는 로컬 파일을 읽고 수정할 수 있으므로 반드시 아래 조건을 지킨다.

1. PROJECT_ROOT 밖 접근 금지
2. .env, secret, key, pem 파일 읽기 금지
3. 삭제 명령 실행 금지
4. rm, sudo, curl | sh, chmod 777 같은 위험 명령 차단
5. apply_patch 전 diff 미리보기 필수
6. 테스트 명령은 허용 목록 기반으로 실행
7. 파일 수정 전 자동 백업 생성
8. 모든 Tool 호출 로그 기록

6. Claude Code 연동 예시

Claude Code에서 MCP 서버를 stdio 방식으로 등록할 수 있도록 실행 스크립트를 제공한다.

예시:

{
  "type": "stdio",
  "command": "node",
  "args": ["/absolute/path/project-code-inspector-mcp/dist/server.js"],
  "env": {
    "PROJECT_ROOT": "/absolute/path/target-project"
  }
}

7. 사용자 시나리오

시나리오 1: 결함 분석

사용자:

로그아웃을 했는데 Redis 세션이 남아있는 것 같아. 원인 찾아줘.

Claude Code 동작:

1. search_code 호출
2. read_file 호출
3. analyze_defect 호출
4. 관련 파일과 원인 설명

시나리오 2: 즉시 수정

사용자:

그럼 바로 수정해줘.

Claude Code 동작:

1. propose_patch 호출
2. 사용자에게 diff 설명
3. apply_patch 호출
4. run_tests 호출
5. explain_patch 호출

8. 완료 기준

- MCP 서버가 정상 실행된다.
- 프로젝트 파일 트리를 읽을 수 있다.
- 키워드 기반 코드 검색이 가능하다.
- 결함 설명을 기반으로 관련 파일을 찾을 수 있다.
- diff 생성이 가능하다.
- diff 적용이 가능하다.
- 테스트 실행이 가능하다.
- PROJECT_ROOT 밖 파일 접근이 차단된다.

9. 우선순위

1차 MVP:

index_project
search_code
read_file
propose_patch
apply_patch
run_tests

2차 확장:

analyze_defect 고도화
심볼 인덱싱
AST 분석
벡터 검색
Git branch 자동 생성
PR 생성
테스트 커버리지 분석

핵심은 처음부터 “자동 수정”까지 열어두되, 삭제/외부경로/위험 명령은 막는 구조로 만드는 겁니다. MCP는 AI가 외부 데이터와 도구를 연결하는 표준이기 때문에, 코드 파일은 Resource로 제공하고 수정·테스트 실행은 Tool로 분리하는 구성이 가장 자연스럽습니다. 공식 TypeScript SDK도 MCP 서버 라이브러리와 transports를 제공하므로 이 명세는 TypeScript 기반 구현이 가장 무난합니다.
