# Claude Code 작업 지시서: 여신 업무 - 전세대출 기능 개발

## 1. 개발 목표

현재 여신 업무 시스템에 전세대출 신청/심사/승인/실행 프로세스를 추가한다.

본 기능은 실제 은행 심사를 완전히 대체하는 것이 아니라, 개발 학습용 은행 업무 프로세스 구현을 목표로 한다.

구현 범위는 다음과 같다. 

- 전세대출 상품 조회
- 전세대출 신청
- 임차계약 정보 등록
- 고객 소득/부채 정보 기반 한도 산출
- 보증기관 선택
- 간이 심사
- 승인/거절 처리
- 대출 실행
- 상환 스케줄 생성

---

## 2. 업무 흐름

전세대출 업무는 아래 순서로 진행한다.

text 고객 로그인   ↓ 전세대출 상품 선택   ↓ 신청 정보 입력   ↓ 임대차계약 정보 입력   ↓ 고객 소득/부채 정보 입력   ↓ 자격 요건 검증   ↓ 대출 한도 산출   ↓ 보증기관 심사 시뮬레이션   ↓ 은행 내부 심사   ↓ 승인 / 거절   ↓ 대출 실행   ↓ 상환 스케줄 생성 

---

## 3. 주요 업무 요건

### 3.1 신청 고객 요건

전세대출 신청 고객은 다음 정보를 보유해야 한다.

- 고객 ID
- 고객명
- 생년월일
- 휴대폰 번호
- 직업 구분
- 연소득
- 기존 부채 금액
- 신용점수
- 무주택 여부
- 세대주 여부

기본 검증 조건은 다음과 같다.

text 1. 고객은 로그인 상태여야 한다. 2. 연소득은 0원 이상이어야 한다. 3. 신용점수는 1~1000 사이 값이어야 한다. 4. 세대주가 아니면 신청 불가 처리한다. 5. 무주택자가 아니면 기본 거절 처리한다. 

단, 실제 금융권에서는 1주택자 허용 여부 등 상품별 예외가 존재할 수 있으나, 본 프로젝트에서는 단순화를 위해 무주택자만 신청 가능하게 구현한다.

## 4. 임대차계약 요건

전세대출 신청 시 임대차계약 정보를 입력받는다.

필수 항목은 다음과 같다.

- 임대차계약번호
- 임대인명
- 임대인 연락처
- 주택 주소
- 주택 유형
- 수도권 여부
- 전세보증금
- 계약 시작일
- 계약 종료일
- 계약금 납입액
- 확정일자 여부
- 전입 예정 여부

기본 검증 조건은 다음과 같다.

text 1. 전세보증금은 0원보다 커야 한다. 2. 계약 종료일은 계약 시작일보다 이후여야 한다. 3. 계약금은 전세보증금의 5% 이상이어야 한다. 4. 수도권 주택은 전세보증금 7억 원 이하만 허용한다. 5. 비수도권 주택은 전세보증금 5억 원 이하만 허용한다. 6. 확정일자가 없으면 심사 보류 상태로 처리한다. 

---

## 5. 보증기관 구분

보증기관은 아래 3가지를 코드화한다.

text HF  : 한국주택금융공사 HUG : 주택도시보증공사 SGI : 서울보증보험 

개발용 기본 정책은 다음과 같이 구현한다.

### HF

text - 안정적인 소득이 있는 직장인 중심 - 연소득 기반 한도 산출 - 보증금 수도권 7억 이하, 비수도권 5억 이하 - 임차보증금의 최대 80% 이내 

### HUG

text - 보증금 반환 안정성 중심 - 주택 가격, 선순위채권 등 목적물 안정성 검토 - 개발 샘플에서는 선순위채권 금액만 입력받아 위험도 계산 

### SGI

text - 고액 전세 또는 일반 보증 대체용 - 개발 샘플에서는 신용점수와 부채비율을 더 강하게 반영 

---

## 6. 대출 한도 산출 규칙

개발용 한도 산출 공식은 다음과 같이 단순화한다.

text 보증금 기준 한도 = 전세보증금 × 80% 소득 기준 한도 = 연소득 × 3.5 부채 차감 한도 = 소득 기준 한도 - 기존 부채 최종 가능 한도 = MIN(보증금 기준 한도, 부채 차감 한도, 상품 최대 한도) 

상품 최대 한도는 기본값으로 222,000,000원을 사용한다.

text 최종 가능 한도 <= 0 이면 거절 신청 금액 > 최종 가능 한도 이면 한도초과 거절 신청 금액 <= 최종 가능 한도 이면 심사 진행

## 7. 심사 상태 코드

전세대출 신청 상태는 다음 코드로 관리한다.

text RECEIVED        : 신청 접수 VALIDATING      : 기본 요건 검증 중 LIMIT_CALCULATED: 한도 산출 완료 GUARANTEE_REVIEW: 보증기관 심사 중 BANK_REVIEW     : 은행 내부 심사 중 APPROVED        : 승인 REJECTED        : 거절 EXECUTED        : 대출 실행 완료 CANCELED        : 신청 취소 

---

## 8. 거절 사유 코드

text NOT_LOGIN             : 로그인 필요 NOT_HOUSEHOLDER       : 세대주 아님 NOT_HOMELESS          : 무주택자 아님 DEPOSIT_LIMIT_EXCEEDED: 보증금 한도 초과 DOWN_PAYMENT_SHORTAGE : 계약금 5% 미만 INVALID_CONTRACT_DATE : 계약 기간 오류 LOW_CREDIT_SCORE      : 신용점수 부족 HIGH_DEBT_RATIO       : 부채비율 초과 LIMIT_SHORTAGE        : 산출 한도 부족 NO_FIXED_DATE         : 확정일자 없음 GUARANTEE_REJECTED    : 보증기관 거절 BANK_REJECTED         : 은행 내부 심사 거절 

---

## 9. 금리 산출 규칙

개발용 금리는 다음 방식으로 산출한다.

text 기준금리 = 3.50% 가산금리 = 신용점수/부채비율/보증기관에 따라 산출 우대금리 = 급여이체, 카드사용, 자동이체 여부에 따라 차감 최종금리 = 기준금리 + 가산금리 - 우대금리 

신용점수별 가산금리:

text 900점 이상 : +0.30% 800점 이상 : +0.50% 700점 이상 : +0.80% 600점 이상 : +1.20% 600점 미만 : 거절 

부채비율별 가산금리:

text 부채비율 30% 미만 : +0.00% 부채비율 50% 미만 : +0.30% 부채비율 70% 미만 : +0.70% 부채비율 70% 이상 : 거절 

보증기관별 가산금리:

text HF  : +0.10% HUG : +0.20% SGI : +0.30% 

우대금리:

text 급여이체 있음 : -0.20% 카드사용 있음 : -0.10% 자동이체 있음 : -0.10% 

최종금리는 최소 2.50%, 최대 8.00% 범위로 제한한다.

## 10. 상환 방식

상환 방식은 다음 2가지를 지원한다.

text MATURITY : 만기일시상환 EQUAL_PRINCIPAL_INTEREST : 원리금균등상환 

전세대출 기본값은 MATURITY로 설정한다.

만기일시상환의 경우:

text 매월 이자만 납부 만기일에 원금 전액 상환

## 15. 테스트 케이스

### 승인 케이스

text - 무주택자 - 세대주 - 수도권 전세보증금 1억 3천만 원 - 계약금 5% 이상 지급 - 연소득 6,500만 원 - 기존 부채 2,000만 원 - 신용점수 820점 - 신청금액 8,000만 원 

예상 결과:

text 승인 상태: APPROVED 한도: 신청금액 이상 금리: 정상 산출 

### 거절 케이스

text 1. 계약금이 보증금의 5% 미만이면 DOWN_PAYMENT_SHORTAGE 2. 수도권 보증금이 7억 초과이면 DEPOSIT_LIMIT_EXCEEDED 3. 비수도권 보증금이 5억 초과이면 DEPOSIT_LIMIT_EXCEEDED 4. 신용점수 600점 미만이면 LOW_CREDIT_SCORE 5. 부채비율 70% 이상이면 HIGH_DEBT_RATIO 6. 신청금액이 산출한도보다 크면 LIMIT_SHORTAGE 7. 확정일자가 없으면 NO_FIXED_DATE 또는 심사보류

## 16. Claude Code 작업 방식

반드시 아래 Sub Agent 순서로 진행한다.

text 1. planner    - 현재 프로젝트 구조 분석    - 기존 여신 업무 구조 파악    - 전세대출 추가 범위 정리  2. architect    - 패키지 구조 설계    - DB 테이블 설계 검토    - 기존 여신 업무와 연계 방식 설계  3. developer    - DTO, Enum, Domain, Mapper, Service, Controller 구현    - 한도 산출, 금리 산출, 심사 로직 구현  4. reviewer    - 코드 품질 검토    - 예외 처리 검토    - 중복/책임 분리 검토  5. tester    - 승인/거절 케이스 단위 테스트 작성    - API 테스트 작성    - 테스트 실행 및 실패 원인 수정

## 17. Claude에게 줄 최종 명령어

아래 내용을 Claude Code CLI에 입력한다.

text 현재 프로젝트의 여신 업무에 전세대출 기능을 추가하려고 한다.  반드시 Sub Agent 기반으로 작업해줘.  진행 순서는 다음과 같다.  1. planner가 현재 프로젝트 구조와 기존 여신 업무 흐름을 분석한다. 2. architect가 전세대출 도메인, DB, API, 서비스 구조를 설계한다. 3. developer가 실제 코드를 구현한다. 4. reviewer가 구현 결과를 리뷰하고 문제점을 찾는다. 5. tester가 테스트 코드를 작성하고 테스트를 실행한다.  전세대출 기능 요구사항은 다음과 같다.  - 전세대출 상품 조회 - 전세대출 신청 - 임대차계약 정보 저장 - 고객 소득/부채/신용점수 기반 한도 산출 - HF/HUG/SGI 보증기관 구분 - 간이 보증 심사 - 은행 내부 심사 - 승인/거절 상태 관리 - 대출 실행 - 만기일시상환 기준 상환 스케줄 생성  구현 시 다음 상태 코드를 사용한다.  RECEIVED, VALIDATING, LIMIT_CALCULATED, GUARANTEE_REVIEW, BANK_REVIEW, APPROVED, REJECTED, EXECUTED, CANCELED  거절 사유 코드는 다음을 사용한다.  NOT_LOGIN, NOT_HOUSEHOLDER, NOT_HOMELESS, DEPOSIT_LIMIT_EXCEEDED, DOWN_PAYMENT_SHORTAGE, INVALID_CONTRACT_DATE, LOW_CREDIT_SCORE, HIGH_DEBT_RATIO, LIMIT_SHORTAGE, NO_FIXED_DATE, GUARANTEE_REJECTED, BANK_REJECTED  개발용 심사 규칙은 다음과 같다.  - 무주택자만 신청 가능 - 세대주만 신청 가능 - 계약금은 전세보증금의 5% 이상 - 수도권 전세보증금은 7억 이하 - 비수도권 전세보증금은 5억 이하 - 신용점수 600점 미만 거절 - 부채비율 70% 이상 거절 - 최종 한도는 전세보증금의 80%, 연소득의 3.5배에서 기존 부채를 차감한 금액, 상품 최대한도 중 가장 작은 값으로 산출 - 상품 최대한도는 222,000,000원 - 전세대출 기본 상환 방식은 만기일시상환  기존 프로젝트의 코드 스타일, 패키지 구조, Mapper 방식, Controller 방식에 맞춰 구현해줘. 불필요한 대규모 리팩터링은 하지 말고, 전세대출 기능 추가에 필요한 최소 변경으로 진행해줘.
